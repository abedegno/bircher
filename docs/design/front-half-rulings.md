# Front half — the rulings taken while implementing

Thirty-four decisions taken during the execution of
`docs/superpowers/plans/2026-09-06-front-half.md`, in the order they were made. The
spec `docs/superpowers/specs/2026-09-05-front-half-design.md` was the binding authority
for all of them: where the plan and the spec disagreed, the spec won, and the plan's
text is what was corrected. Each ruling names what it cost if it turned out wrong.

One was reversed on the evidence — the last entry says which and why.

- **Task 1.** the brief names no mutation for Task 1 (a plan gap); the implementer's self-chosen mutation (drop the run_id filter in facts_of_kind) is accepted as the task's mutation — costs nothing if wrong beyond one untested guard, which round 1 pins.
- **Task 2.** the plan's parse() gates value capture on `valued` only; the original consumed the token after any _METHOD_FLAGS entry. Restore the OR (method flags always take a value) — a latent operand leak for a future `--method` rule; costs nothing if wrong beyond one extra captured token on a rule nobody writes.
- **Task 2.** break the contract↔effects cycle by extracting EffectClass into kernel/effect_class.py (re-exported by effects) rather than monkey-patching module attributes — costs a new tiny module; wrong only if something imports EffectClass by a path that the re-export does not cover.
- **Task 4.** the brief's mutation prediction was wrong (test gap, not code); the three-way title check stays and gains a binding test — costs one test; wrong only if the coordinator can legitimately journal a create whose body title differs from its key, which the design forbids (the title IS the key).
- **Task 5.** only None means "unset"; any other non-dict project_config is ValueError before the run row is written — the plan's `project_config or {}` was wrong; costs nothing if wrong beyond refusing a caller that passed [] meaning "none", which no caller does (the runner passes {}).
- **Task 6.** real and load-bearing for the back half, not for Task 6's files — carried into Task 20 as an explicit item: before any `_kernel_adopt_run`/`_kernel_dispatch` in the sweep's fallback branch and in recover_pr_cmd, read `_kernel_pending` and skip with a log line when halted or pending (mirror the deferred branch's empty-generation guard at run-queue.sh:1946-1968). Costs a skipped recovery until a human reconciles, which is the design.
- **Task 7.** the implementer's beyond-brief fix stands — `_merge_is_authorized` and `_reviewer_of` now ignore front-half verdicts (reproduced: a spec reviewer's accept could authorize a merge once front-half verdicts carried a binding_hash). - **Final review.** the concern is real and the fix is the COORDINATOR's, not the kernel's. The spec states the kernel rule outright (§3: record_turn_ended is "refused for a session that is not the one the newest satisfied sess-prompt of the phase and epoch names"), so `_check_turn_ended` and ruling 15 stand and the spec is not amended. What is wrong is that `human._send`'s two callers (reply_refusals at human.py:227, the park answer at :286) send prompts NOBODY AWAITS into the same phase and epoch as an awaited turn; on the crash-recovery pass the seat's prompt is already satisfied, so an owed reply to an older session of that phase and epoch goes out first, becomes the phase's newest, and the seat's record_turn_ended — and its submit — are refused. Reachable: a request_revision opens a new author session in the same phase and epoch while a refusal dismissed in the old one may still be unanswered. The round catches the NotAuthorized so the run recovers by burning a seat, but §7 claims a crash anywhere in that sequence is repaired from the journal, and this is a counterexample to the claim. Fix: one guard in `_send` — defer while the phase and epoch's newest satisfied prompt names another session, has no turn_ended, AND that session is the one the newest satisfied sess-create of the phase and epoch delivered (the seat). The third clause is load-bearing: without it a phase whose newest prompt is itself an unawaited reply would starve every later reply forever. Costs, if wrong, a reply to a dismissed refusal delayed by one pass.
- **Reversed — the final review's guard.** The MEDIUM is right: the guard's third condition asked whether the blocking session was the phase's newest sess-create, not whether a turn was genuinely awaited, so a park answer addressed to that session met all three conditions with nothing awaited and held back every other reply owed in the phase and epoch — and `reply_refusals` has no caller outside a park, so once the human answered, the reply was never attempted again (§4: the human is told, "not never"). Checking reachability of the defect I had ruled in: BOTH callers of `_send` sit inside `human_pass`; `human_pass` runs only where `current_park` is not None (phases.py:253 and :304); `run_loop` reaches an author or review round only where it IS None. A park is therefore never current while a turn is awaited, so no prompt this module sends can displace one, and the kernel's phase-scoped `_check_turn_ended` is safe as it stands. The guard defended an unreachable path and starved a reachable one. Reverted in 708a9e8, which states the invariant in `_send`'s docstring so a later pass that sends a prompt outside a park is told what it must re-establish. Cost, if this reversal is wrong: the crash-window refusal returns, and it costs one seat and is caught.
